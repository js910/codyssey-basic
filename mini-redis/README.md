# Mini Redis

키를 붙여 값을 저장하고 값을 빠르게 찾아오는 작은 저장소입니다.
Redis의 기본 원리를 익히기 위해 해시맵, 이중 연결 리스트, 최소 힙을 직접 구현했습니다.
Python 3.8 이상에서 실행할 수 있고, 추가로 설치할 라이브러리는 없습니다.
데이터는 실행 중인 메모리에만 저장되므로 프로그램을 종료하면 사라집니다.

## 파일 구조와 역할

```text
mini-redis/
├── main.py                 # 프로그램 시작
├── mini_redis/
│   ├── __init__.py
│   ├── cli.py              # 명령어 읽기, 실행, 결과 출력
│   ├── store.py            # 값 저장, 사용 순서와 만료 시간 관리
│   └── structures/
│       ├── __init__.py
│       ├── linked_list.py  # 이중 연결 리스트
│       ├── hash_map.py     # 해시맵
│       └── min_heap.py     # 최소 힙
├── tests/
│   ├── __init__.py
│   └── test_mini_redis.py   # 자동 테스트
└── README.md
```

- **해시맵**: 키를 숫자로 바꿔 저장 위치를 찾습니다. 서로 다른 키가 같은 위치에 배정되면 연결 리스트에 이어서 저장합니다(체이닝). 저장 공간이 75%를 넘게 차면 공간을 두 배로 늘립니다.
- **이중 연결 리스트**: 각 항목이 앞뒤 항목을 기억합니다. 저장소가 각 항목의 위치를 가지고 있어, 값을 조회했을 때 목록 전체를 찾지 않고 맨 앞으로 옮길 수 있습니다. 앞에는 최근 사용한 키, 뒤에는 오래 사용하지 않은 키가 놓입니다.
- **최소 힙**: 가장 작은 값이 항상 맨 위에 오도록 관리합니다. 만료 시각을 넣으면 가장 먼저 만료될 키를 바로 확인할 수 있습니다.

연결 리스트의 삽입·삭제·이동은 O(1), 해시맵 조회는 평균 O(1)입니다.
해시맵의 키가 한곳에 몰리면 조회가 느려질 수 있고, 공간을 늘릴 때는 기존 항목을 다시 배치합니다.
힙의 삽입·삭제는 O(log n)으로, 데이터가 늘어도 작업 수는 완만하게 증가합니다.

과제 조건에 맞춰 핵심 구현에서 `dict`, `set`, `collections`, `heapq`를 사용하지 않았습니다.
파이썬 리스트는 버킷과 힙의 배열 저장 공간으로 사용합니다.
네트워크 통신, 파일 저장, 선택 보너스 기능은 포함하지 않았습니다.

## 실행 방법

프로젝트 폴더에서 다음 명령을 실행합니다.

```console
python main.py
```

`mini-redis> `가 나오면 명령어를 입력하면 됩니다.
공백이 있는 값은 큰따옴표로 감싸고, 종료할 때는 `exit` 또는 `quit`을 입력합니다.
명령어 이름은 대문자와 소문자 모두 사용할 수 있습니다.

## 사용할 수 있는 명령어

| 명령어 | 설명 |
| --- | --- |
| SET key value | 키에 값을 저장합니다. 같은 키가 있으면 값을 바꾸고 기존 만료 시간을 없앱니다. |
| GET key | 키에 저장된 값을 가져옵니다. 없으면 `(nil)`을 반환합니다. |
| DEL key | 키를 삭제합니다. 삭제했으면 1, 없으면 0을 반환합니다. |
| EXISTS key | 키가 있으면 1, 없으면 0을 반환합니다. |
| DBSIZE | 현재 저장된 키가 몇 개인지 알려줍니다. |
| KEYS | 현재 저장된 모든 키를 보여줍니다. |
| CONFIG SET maxmemory bytes | 저장할 수 있는 최대 용량을 바이트 단위로 정합니다. 0이면 제한이 없습니다. |
| INFO memory | 현재 사용 용량, 최대 용량, 용량 부족으로 제거된 키 수를 보여줍니다. |
| EXPIRE key seconds | 키가 몇 초 뒤에 사라질지 정합니다. 키가 있으면 1, 없으면 0을 반환합니다. 0초 이하는 즉시 삭제합니다. |
| TTL key | 만료까지 남은 초를 보여줍니다. 만료 시간이 없으면 -1, 키가 없으면 -2입니다. |

`TTL`의 남은 시간은 소수점 아래를 버립니다. 예를 들어 2.8초가 남았다면 2입니다.
정수 입력은 부호 있는 64비트 범위이며, 최대 용량에는 음수를 입력할 수 없습니다.

## 용량이 부족하면 어떻게 되나요?

키와 값을 UTF-8로 바꿨을 때의 바이트 수를 더해 사용 용량을 계산합니다.
자료구조 자체가 차지하는 공간은 과제 기준에 따라 제외합니다.

새 값을 저장해 용량을 넘으면 가장 오랫동안 사용하지 않은 키부터 지웁니다.
이 방법을 **LRU**라고 합니다. `SET`이나 성공한 `GET`으로 사용한 키는 삭제 순서가 뒤로 밀립니다.
키가 있는지만 확인하는 `EXISTS`와 만료 시간을 다루는 명령은 이 순서를 바꾸지 않습니다.

```text
mini-redis> CONFIG SET maxmemory 30
OK
mini-redis> SET user:1 "Alice"
OK
mini-redis> SET user:2 "Bob"
OK
mini-redis> SET user:3 "Charlie"
OK
mini-redis> GET user:1
(nil)
mini-redis> INFO memory
used_memory:22
maxmemory:30
evicted_keys:1
```

세 번째 값을 저장하면 총 33바이트가 되어, 가장 오래된 `user:1`을 지웁니다.
남은 두 항목은 22바이트이고, 용량 부족으로 제거된 키는 1개입니다.

키 하나와 값 하나만으로도 제한 용량을 넘으면 저장하지 않고 `OOM` 오류를 반환합니다.
이때 같은 키의 기존 값과 만료 시간은 유지됩니다.
최대 용량을 낮추는 명령 자체는 키를 지우지 않으며, 다음 저장 성공 시 필요한 만큼 지웁니다.

## 만료 시간은 어떻게 관리하나요?

키에 정한 유효 시간을 **TTL**이라고 합니다.
명령어를 실행할 때 시간이 지난 키를 먼저 정리하므로, 만료된 키는 없는 키처럼 처리합니다.
입력을 기다리는 동안 별도로 작업하지 않고 다음 명령을 실행할 때 정리합니다.
만료로 사라진 키는 용량 부족으로 제거된 키 수에 포함하지 않습니다.

만료 시각은 최소 힙에 넣어 가장 먼저 만료될 키를 빠르게 찾습니다.
만료 시간을 바꾸거나 같은 키를 다시 저장하면, 이전 기록이 새 값을 지우지 않도록 기록 번호를 확인합니다.
더 이상 쓸 수 없는 기록이 많이 쌓이면 힙을 다시 정리합니다. (`힙 기록 수 > max(64, 현재 저장된 키 개수 * 2)`)

## 테스트 실행

```console
python -m unittest discover -s tests -v
```

자료구조의 기본 동작, 메모리 계산, 오래된 키 제거, 만료 시간, 잘못된 명령어 등을 확인합니다.
만료 시간 테스트는 시간을 직접 바꿀 수 있는 테스트용 시계를 사용하므로 실제로 기다리지 않습니다.
